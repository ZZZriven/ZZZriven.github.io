GEPA：从执行轨迹反思并演化提示

GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning

Lakshya A Agrawal 等

首次提交 2025.07.25已核实修订 2026.02.14 · v2解析整理 2026.09.12
arXiv 原文阅读 PDF
IN A NUTSHELL

让模型阅读推理和工具执行轨迹，用自然语言诊断失败，再通过候选种群与Pareto选择积累互补的提示策略。

改进对象
单模块或多模块提示
反馈来源
执行轨迹、诊断文字与任务评价分数
证据边界
摘要与官方实现说明；未通读全文，比较结论限于论文设置
01
RESEARCH PROBLEM

研究问题

稀疏标量奖励通常不能直接说明失败原因，强化学习适配新任务又可能需要大量轨迹。论文研究能否从少量可读执行信息中提炼高层规则，并通过提示更新提高单个或复合LLM系统的表现。

02
INSIGHT

核心洞察本站解读

轨迹中包含的错误位置、工具返回和推理过程，比一个最终分数提供更多可操作信息。反思模型可将这些信息压缩成修改建议，而保留不同任务子集上的优势候选，有利于积累互补经验。

03
OBSERVATION

关键观察

论文方法围绕完整轨迹进行语言反思，并从自身历史候选的Pareto前沿选择与组合经验。官方实现说明也将评价器返回的诊断信息作为优化输入，表明反馈质量是重要的接口要求。

04
METHOD

方法解析

先选取候选系统并在小批任务上执行，记录轨迹和反馈；反思模型据此提出提示变体并测试。候选池保留不同任务上的有效方案，并可合并互补模块，反复进行选择、变异和评价。

05
RESULTS & EVIDENCE

实验与结论

更新版摘要报告六项任务上平均优于GRPO约6%，最多使用少35倍的轨迹，并超过提示优化基线MIPROv2。这些是论文给定模型和预算下的结果，不能解读为提示优化普遍胜过所有强化学习方法。

06
LIMITATIONS

局限与边界本站解读

本条核对摘要与官方方法说明，未通读论文全文或复现实验。优化依赖反思模型、可用轨迹及评价预算；保存提示并不更新基础模型参数，减少轨迹数量也不必然等于同比例降低总算力成本。

07
OUTLOOK

未来展望本站解读

编辑展望：可进一步比较反馈只有分数、包含错误文本以及包含完整轨迹时的收益，并在预算相等时分析反思成本。长期应用还应测试候选合并、验证集过拟合以及迁移后规则冲突。

THE RSI CONNECTION · 本站判断

与递归自我改进的关系

编者归类：属于可持久保存的提示层改进，适合与AFlow的结构搜索和ACE的记忆积累对照。GEPA使用反思来改进任务系统，但这里的证据没有表明它递归修改了自己的优化算法。
