SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering

SWE-agent：面向 Agent 设计代码操作接口

John Yang 等

Submitted 2024.05.06Verified Version 2024.11.11 · v3Note Updated 2026.09.12
arXivRead PDF
SUMMARY

通过更适合 model 的 search、编辑、feedback 与 context 接口，提升在真实代码仓库中的问题修复能力。

Improvement Target
Software Engineering Interfaces & Tools
Feedback
仓库 search 结果、编辑后的内容、语法检查、代码执行与测试输出。
Evidence Scope
核验摘要、v3 元数据及正文第 2–5 节；数字对应原论文完整集与 Lite 子集，未独立复现。
01

Research Problem

能生成代码不代表能可靠完成仓库级修复：model 还要定位文件、编辑局部、读懂错误并执行测试。论文研究这些操作的接口设计如何影响成功率，以及普通命令行为何可能消耗大量无效步骤。

02

Insight本站解读

Agent 的表现取决于 foundation model 与操作环境的配合。紧凑编辑、清楚 feedback 和适量 context 可以改变同一 model 的有效能力；编辑理解是，系统层改进应把工具造成的摩擦与 model 本身的知识缺口分开测量。

03

Observation

ablation 中，逐条查看 search 命中可能让 model 穷尽无关结果，整文件展示也可能比适当窗口更差。编辑后的语法检查有助于阻止错误传播；这些现象说明给出更多信息或更多自由度并不必然改善操作。

04

Method

设计少量 search、定位、文件查看与局部编辑命令，在修改后直接展示新内容并检查语法。系统压缩旧观察，保留当前关键信息；model 交替提出操作和读取 execution feedback，直至提交修复补丁。

05

Results

原论文中，GPT-4 Turbo 配合该接口在完整 SWE-bench 上解决 12.47% 的任务，在 Lite 子集解决 18.00%。这些是特定历史 model 与预算下的修复成绩，用于说明接口设计作用，不代表当前最高水平。

06

Limitations本站解读

接口来自人工行为分析和配置 search，运行中的 Agent 没有自动演化自身工具。它修改的是目标仓库，foundation model 也冻结。因此代码修改、execution feedback 与高分修复本身，均不足以构成 Recursive Self-Improvement。

07

Outlook本站解读

编辑展望：可以把接口作为 self-improvement 目标，要求候选版本在未见仓库、同 model 与同预算下比较，并保留操作失败率。这样能检验新的工具究竟提高通用修复效率，还是只适应某个 benchmark 的文件模式。

EDITORIAL NOTE · 本站判断

Relation to RSI

编辑归类为相关能力基础：RSI 系统若要编辑自己的实现，需要可靠的代码定位、修改和验证组件。SWE-agent 提供这一工程前提，但原论文实验没有让工具的产物回过头来增强其自身改进能力。
