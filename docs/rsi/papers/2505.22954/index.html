Darwin Godel Machine: Open-Ended Evolution of Self-Improving Agents

Darwin Gödel Machine：让 Agent 改写自己

Jenny Zhang 等

Submitted 2025.05.29Verified Version 2026.03.12 · v3Note Updated 2026.09.12

SUMMARY

通过修改自身代码、在编程 benchmark 上验证效果，并保留多样化的 Agent 档案，探索开放式 self-improvement。

Improvement Target
Agent Code
Feedback
来自编程 benchmark 的执行结果、测试得分与评估日志；通过外部可执行任务验证候选 Agent。
Evidence Scope
已核验摘要及正文第 1、3、4 节相关内容。数字为作者在论文评估设置下报告，尚未独立复现；未证明无界或自加速改进。
01

Research Problem

由人设计的 Agent 结构固定后，能否自行发现更好的工具和 workflow？

02

Insight本站解读

self-modification 可能需要先保留暂时不领先的方案，再把它们作为后续创新的起点。DGM 将经验验证与多分支档案结合，使新工具或流程有机会在后代中发挥作用；recursion 之处在于负责修改代码的 Agent 也使用演化后的自身实现。

03

Observation

作者观察到，保留多样化 Agent 档案能帮助 search 越过局部最优，某些暂时较弱的版本也能产生更强后代。论文还报告未参与 search benchmark 上的迁移；这些证据支持代码改进具有一定可迁移性，但不等于任意任务上的持续增长。

04

Method

从历史 Agent 档案中选择个体，借助 foundation model 修改其代码，再用编程任务评估并保留有价值的变体。

05

Results

论文报告，冻结 foundation model 后，通过代码 self-modification，SWE-bench Verified 的 200 题子集成绩由 20% 提升至 50%；完整 Polyglot benchmark 由 14.2% 提升至 30.7%。原文还报告跨 benchmark、未参与 search 任务的迁移，结论仍限于所用 model、任务与 search 预算。

06

Limitations本站解读

foundation model weights 冻结，开放探索中的档案维护与父代选择也固定；benchmark 得分提升是代码系统改进证据，不能直接推出全系统无约束 recursive evolution。

07

Outlook本站解读

本站展望：将已有跨 benchmark 迁移检验扩展到更长演化周期、更广的未见任务与不同 foundation model，并报告多次运行方差和完整 search 成本。进一步隔离 self-modification 机制、档案多样性与 inference budget 的贡献，才能判断改进效率能否持续提高。
