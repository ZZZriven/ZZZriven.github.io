AFlow: Automating Agentic Workflow Generation

AFlow：通过 tree search 自动生成 Agent workflow

Jiayi Zhang 等

Submitted 2024.10.14Verified Version 2025.04.15 · v4Note Updated 2026.09.12
arXivRead PDF
SUMMARY

把 workflow 优化写成代码空间 search，用 Monte Carlo tree search 的变体组织候选、execution feedback 和修改经验，减少人工编排。

Improvement Target
Workflow Structure & Prompts
Feedback
任务执行成绩与树结构修改经验
Evidence Scope
六个 benchmark；search 空间、执行 model 与评价函数受设定限制
01

Research Problem

复杂任务往往需要多个 model 调用及明确的执行顺序，但人工编排成本高；自动方法也容易被固定结构和低效 search 限制。论文希望同时探索 prompt 与 control flow，并有效复用失败和成功的修改经验。

02

Insight本站解读

workflow 可以视作 model 调用节点与代码表达的连接关系。将 search 历史保存成树，能够从多个有潜力的候选继续扩展；将常见操作组成算子，则可为巨大代码空间提供便于 search 的先验结构。

03

Observation

正文实际 search 主要放开 prompt 与连接代码，而固定 model、温度和输出格式以控制复杂度。树结构保存父子修改经验，executor 提供任务成绩，使候选选择不仅依赖 language model 对自身方案的评价。

04

Method

AFlow 循环执行候选选择、LLM 代码扩展、workflow 执行评价和经验回传，使用 MCTS 变体平衡探索与利用。search 在给定算子集合内推进，到预算上限或满足收敛条件时选择表现较好的 workflow。

05

Results

论文摘要报告六个数据集上相对比较 baseline 平均提升 5.7%，并展示小 model 配合优化流程的成本优势。这些结果支持 workflow search 的实用价值，但具体优势依赖任务、执行 model 与所比较的流程。

06

Limitations本站解读

自动化发生在人工指定的任务、算子、评价函数和 search 预算内；主要实验并未同时 search model weights 或评测标准。文中的低 reasoning 费用比较也不应自动解释成包含离线 search 成本的全部生命周期成本。

07

Outlook本站解读

编辑展望：后续应同时报告 search 开销、部署调用量和 cross-task transfer 收益，判断何时能摊薄优化成本。若把算子创建或 search strategy 也交给系统修改，需要单独检验这些修改是否提升未来 search 效率。

EDITORIAL NOTE · 本站判断

Relation to RSI

以固定 search 流程和 LLM optimizer 改写任务 workflow，保存可复用的 prompt 与节点连接，属于 Persistent System Improvement。论文区分 optimizer 和 executor；被 search 的 workflow 改善，没有展示 MCTS 或 optimizer strategy 自身被改写并接手后续 search。
