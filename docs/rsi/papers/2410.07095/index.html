MLE-bench: Evaluating Machine Learning Agents on Machine Learning Engineering

MLE-bench：评估 Agent 能否完成 machine learning engineering

Jun Shern Chan 等

Submitted 2024.10.09Verified Version 2025.02.26 · v6Note Updated 2026.09.12
arXivRead PDF
SUMMARY

基于 75 项公开 machine learning 竞赛评价 Agent 的数据准备、训练和实验能力，用历史人类成绩建立参照，同时讨论资源扩展与 data contamination。

Improvement Target
ML Engineering Evaluation
Feedback
竞赛评分、历史人类门槛与过程合规检查
Evidence Scope
核验 arXiv 摘要中的 machine learning engineering 评测与历史成绩；benchmark 分数并不直接证明系统自主更新。
01

Research Problem

编程问答或短代码 benchmark 不足以衡量自动 AI 研发：完成 machine learning 项目需要处理数据、训练 model、安排实验并生成有效提交。论文因此寻找可重复评价、具有明确结果和人类参照的工程任务集合。

02

Insight本站解读

machine learning 竞赛同时具备现实数据、可执行目标和公开成绩，可将多步骤工程工作压缩为可评分任务。评价对象是 model 与 Agent 框架的组合，预算和试验安排因此会直接影响能力估计。

03

Observation

论文把数据准备、model 训练与实验运行列为主要能力，并比较资源扩展和 pre-training data contamination 的影响。这说明竞赛成绩必须结合代理实现、计算预算和任务可见性解释，不能仅凭单一分数归因为 Agent 自主学习。

04

Method

从公开平台整理 75 项 machine learning 竞赛，构建数据与评分流程，以原竞赛公开榜单作为人类参照。研究使用开源 Agent scaffold 测试多个 model，并通过不同资源配置和污染分析考察成绩变化的来源。

05

Results

原论文最优配置 o1-preview 加 AIDE 在 16.9%的竞赛达到至少铜牌水平。这里指达到门槛的竞赛比例，并非在所有参赛者中排名前 16.9%；它也是原论文历史结果，不是当前公开榜单最高成绩。

06

Limitations本站解读

竞赛工程成绩不直接等于自主发现新算法或 Recursive Self-Improvement。数据泄漏、历史任务可见性、训练资源与代理脚手架都会影响比较；原论文的历史结果必须保留 model 和预算 context。本条核验摘要，未独立重跑竞赛。

07

Outlook本站解读

编辑展望：更适合用固定预算、held-out tasks 和版本明确的评分协议比较改进前后系统。长期评估可加入失败日志、任务约束遵守情况及跨竞赛迁移，减少把试验堆量或数据泄漏误当作能力增长。

EDITORIAL NOTE · 本站判断

Relation to RSI

编者归类：这是 RSI 相关 AI 研发能力的外部测量工具，并非 self-improvement 算法。它可检测改进后的系统是否更会完成 machine learning 任务，但还需额外记录系统更新过程，才能将分数变化归因于自主学习。
